# Data-quality gap register

Reviewed: **2026-09-06**. Companion to [Data lineage and transformation rules](data-lineage.md).

Current correctness limits and proposed acceptance cases for trace/evaluation decisions. Entries remain open, without delivery commitments or scope changes; deferred capacity belongs in the [wishlist](backlog.md).

Evidence labels:

- **Reproduced:** observed in a focused synthetic audit case.
- **Source review:** supported by code, without a dedicated audit regression test.
- **Existing tests:** verifies this or a related boundary, not resolution of the wider gap.
- **Live observation:** observed in the running dashboard and stored records; not a synthetic regression test.

## Analysis practice while gaps remain

Preserve original files and analyze a fixed database copy. Record code revision/source snapshot, input hashes, session/source selection, import outcomes, timing groups, and exclusions. AgentBoard does not generate this manifest; record it manually.

Prefer comparing the same source and timing method. Treat incomplete/unsupported coverage as missing evidence, not zero cost. Keep dummy runs separate from actual model runs. Verify human authorship before using prompt counts or waits as human-productivity measures. Do not derive correctness or task-success scores from an `ok` status.

Also capture session metadata/classification, metric-specific raw evidence, and query/analysis definitions; event export alone is insufficient. Codex raw archive behavior is defined in [lineage §3.5](data-lineage.md#35-raw-archive-and-export); configurable retention and complete event-to-source linkage remain open.
