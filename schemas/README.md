# Codex app-server schema baseline

Keep a reviewable copy of the app-server contract generated by a specific Codex CLI. The [manifest](codex-app-server/manifest.json) records the producing CLI version, generator flags, documentation source, and SHA-256 of every [generated file](codex-app-server/generated). Generated bytes are retained unchanged; Git history preserves earlier baselines.

This bundle includes experimental methods and fields because it is generated with `--experimental`. Their presence does not mean AgentBoard enables or supports them. These schemas describe the app-server API, not persisted rollout JSONL. They do not establish human authorship or timing semantics. See the [rollout compatibility policy](../docs/specification.md#35-codex-rollout-compatibility-policy).

## Commands

Run from the repository root with Python 3.11 or newer; the script uses only the standard library:

```sh
python scripts/codex_schemas.py verify
python scripts/codex_schemas.py check
python scripts/codex_schemas.py update
```

| Command | Behavior |
| --- | --- |
| `verify` | Offline: check manifest provenance, exact file inventory/hashes, JSON decoding, and local `$ref` pointers. Included in the regular pytest suite; Codex is not required. |
| `check` | Generate into a temporary directory using the installed `codex`; compare CLI version and files with the baseline. Report added, removed, and changed files. Leave the repository unchanged. |
| `update` | Regenerate and replace the managed baseline after generation checks pass, removing obsolete files. Preserve the previous baseline on generation or installation failure. Identical output is a no-op. |

`check` exits 1 for drift; all commands exit 2 on errors and 0 on success. Use `--codex /path/to/codex` with `check` or `update` to select a specific installation, including a desktop-bundled binary when available. The script does not install or upgrade Codex, start a conversation, or schedule monitoring. Its underlying generation command is:

```sh
codex app-server generate-json-schema --out TEMP/generated --experimental
```

No timestamps or machine-specific paths enter the manifest, so repeated generation from the same CLI produces a clean comparison. A CLI version change is reported even when schema bytes are identical. Missing schemas, unresolved pointers, or unfamiliar external references fail validation for review rather than being silently accepted. These checks do not perform full JSON Schema validation, classify breaking changes, or prove client compatibility.

## Codex upgrade workflow

1. After installing a Codex upgrade, run `check` against the executable intended for AgentBoard. Do not infer its version from a different desktop or CLI installation.
2. If drift is reported, run `update`, then review `git diff --stat -- schemas/codex-app-server` and `git diff -- schemas/codex-app-server`. Inspect the manifest version/flags and changes affecting AgentBoard's requests and notifications, especially [native continuation](../backend/agentboard/resume.py).
3. Adapt affected app-server integration code and its tests. Separately review raw rollout fixtures when the producer changes; this API bundle cannot validate their format. Advance the rollout mapping version only when rollout normalization semantics change.
4. Run `check` again and the [regular verification commands](../README.md#examples-and-validation). Commit the generated bundle, manifest, relevant integration changes, and documentation together. The baseline identifies inspected schema output, not a claim that every method or Codex release is supported.

The baseline is updated explicitly. Routine tests verify its integrity offline; installed-version drift is checked when upgrading Codex or changing its integration. No recurring job is configured.
